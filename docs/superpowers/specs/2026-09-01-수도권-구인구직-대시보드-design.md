# 수도권 구인구직 대시보드 — 설계

- 작성일: 2026-09-01

- 동반 산출물: 「서울 청년 사무직 고용감소와 구직연계 시사점」 보고서
- 화면 목업: https://claude.ai/code/artifact/928c2cec-e6ec-4dd0-af7c-ea86b77770d9

## 1. 무엇을 만드는가

서울고용센터에 보고서와 함께 넘길 **모바일 대시보드**다. 고용행정통계와
직종별사업체노동력조사를 한 화면에 얹되, 두 자료의 시점·범위·분류가 다르다는 사실을
화면이 숨기지 않는다.

쓰는 사람은 둘이다.

- **센터 기획·지원 담당자** — 관할 구인구직 규모와 추세를 확인하고 숫자를 보고서로 옮긴다.
- **상담창구 직업상담사** — 구직자 앞에서 특정 직종의 자리 사정을 꺼내 보인다.

배포는 GitHub Pages. 저장소는 `사무직감소\06_대시보드\` 하나이고, 상위 폴더의 보고서·
피보험자 원자료·구직자 마이크로데이터는 저장소 밖에 남는다. 공개되는 것은 공개 API에서
받은 집계값뿐이다.

## 2. 자료

다섯 가지를 쓴다. 넷은 EIS OLAP, 하나는 KOSIS다.

| 자료 | 측정값 | 주기 |
|---|---|---|
| 유효구인구직현황(전체) | 유효구인인원(명) · 유효구직건수(건) | 월 |
| 구인구직취업현황(월) | **취업건수만** 씀 | 월 |
| 월별 피보험자현황 | 피보험자수 · 취득자수 · 상실자수 | 월 |
| 월별 경력직노동력 이동현황 | 경력이동자수 | 월 |
| 직종별사업체노동력조사 (KOSIS) | 현원·구인·채용·미충원·부족·부족률·채용계획인원 | 반기 |

### 2.1 유효를 쓰고 신규를 쓰지 않는다

「구인구직취업현황(월)」의 신규구인·신규구직은 화면에 올리지 않는다. 현장에서 거의 쓰지
않는다는 사용자 판단이며, 유효 쪽이 "지금 지원할 수 있는가"라는 상담 질문에 곧바로
답한다. 이 리포트는 **취업건수를 얻기 위해서만** 수집한다.

- **유효구인인원(명)** — 월말 시점에 마감되지 않은 구인신청건의 모집인원.
- **유효구직건수(건)** — 월말 시점에 마감되지 않은 구직신청건수. **사람 수가 아니다.**
  1인당 여러 건 등록이 가능하다.
- **구인배수** = 유효구인인원 ÷ 유효구직건수. 1 미만이면 일자리 부족.

### 2.2 지역 축은 두 벌이고 뜻이 다르다

EIS 통계정보 원문 그대로다.

| 축 | 유효구인인원 | 유효구직건수 |
|---|---|---|
| **(근무지역)** 시도·시군구 | 구인업체 모집 근무지역 | 구직자 **희망** 근무지역 |
| (지역별) 시도·시군구 | 사업장 소재지역 | 구직자 **거주**지역 |

**화면은 (근무지역) 축으로 통일한다.** 그래야 구인과 구직이 같은 잣대가 된다 — "서울에
난 자리" 대 "서울에서 일하려는 구직건". 거주지 기준은 다른 질문("관할 주민의 구직 실태")에
답하는 축이라 지금은 쓰지 않는다.

"등록한 센터"라는 축은 이 리포트에 없다. 항목 정의에 기관·등록·접수·센터라는 말이
한 번도 나오지 않는다(검색 0건 확인).

### 2.3 자료마다 바닥이 다르다

| 자료 | 지역 | 직종 | 산업 |
|---|---|---|---|
| 유효구인구직 | 시군구 | **소분류** | **대분류만** |
| 피보험자 | 시군구(사업장) | **소분류** | **소분류** |
| 경력직 이동 | **시도까지** | **없음** | **대분류만** (현·이전) |
| 직종별사업체노동력조사 | **시도까지** | 시도는 **중분류**, 소분류는 전국만 | 시도는 **대분류**, 중분류는 전국만 |

그래서 **직종별 탭은 소분류까지 내려가고, 산업별 탭 스위처는 대분류에서 멈춘다.** 산업을
중분류까지 열면 네 카드 중 피보험자 하나만 남아 탭이 무너진다.

### 2.4 축이 비어 있는 자리

- **유효구인에는 성·연령이 없다.** 남녀고용평등법·연령차별금지법에 따라 모집 시 성별·
  연령별 구인인원을 제시하지 못한다. EIS가 명시한다.
- **유효구직에는 산업·규모가 없다.** 수집하지 않는 항목이다. 산업축 값이 전부 0이고
  '해당없음'에 총계가 몰려 있는 것으로 재확인했다.

이 때문에 **총괄 스위처에 연령을 두지 않는다.** 연령을 고르면 구직 칸만 바뀌어 구인배수의
분자·분모 기준이 어긋난다. 연령은 구직 쪽 그래프 안에서만 건다.

### 2.5 EIS 오픈API로는 구인을 못 받는다

`/opi/joApi.do`는 시군구·성별·연령이 **모두 필수 파라미터**인데, 위 법령 때문에 구인인원을
성·연령으로 배분할 수 없어 구인 칸이 구조적으로 항상 0이다(강남·종로 × 2024·2026 확인).
또한 IP당 호출 한도가 있어 100여 회에서 `HITS_EXCEEDED`가 뜬다. **오픈API는 쓰지 않는다.**

### 2.6 KOSIS 표 이어붙이기와 코드 개편

| 표 | 기간 | 직종 코드 | 항목 수 |
|---|---|---|---|
| `DT_118N_DEN052` | 2021~2023 | `keco2018_` | — |
| `DT_118N_DEN065` | 2024~2025 | `keco2018_` | 182 |
| `DT_118N_DEN062` | 2026~ | **`keco2026_`** | **186** |
| `DT_118N_DEN061` | 2024~ (산업별) | `2026INDUSTRY_` | 93 |

2026년 표에서 **직종 코드 체계가 바뀌었다.** 이어 붙일 때 코드 매핑이 필요하고, 경계에서
값이 튀지 않는지 검사해야 한다. 조회 시 `prdSe`는 반기 = **`S`** 다(`H` 아님).

## 3. 지역 — 센터 매핑

`data/center_map.json` 한 파일이 시군구를 센터로 묶는다. 수집기도 화면도 이 파일만 본다.

- **시군구 70개 → 센터 39개** (서울 25/11, 경기 31/25, 인천 14/3)
- 이중배정 0, 누락 0 — 검증 스크립트가 통과해야 빌드된다.

판단이 필요했던 자리와 근거:

1. **고용복지센터·출장센터 7곳**(가평·군포·양평·여주·연천·포천·강화)이 상위 고용센터와
   관할이 겹친다. 상위 센터로 접었다. 접지 않으면 센터별 합계가 이중계상된다.
2. **화성시**는 수원·화성 두 센터가 읍면동으로 나눠 갖지만 EIS는 시군구까지만 준다.
   화성고용센터로 통째 배정한다.
3. **가평군**은 강원지청 춘천고용센터 관할이다. 수도권 목록에 강원 소속 센터가 하나 들어온다.
4. **인천 신설구** — 제물포·영종은 인천고용센터, 서해·검단은 인천서부고용센터.

코드 함정 둘:

- **경기 일반구 코드를 쓰지 않는다.** `41110 수원시`와 `41111 장안구`가 나란히 있어
  둘 다 받으면 이중계상된다. 시 단위만 쓴다.
- **인천은 개편 전후 코드가 공존한다.** 같은 달에 옛 코드와 새 코드를 함께 더하지 않는다.
- 폐지 코드 `41283`·`41710`·`41730`·`41810`은 제외한다.

### 4.4 센터별

| # | 카드 |
|---|---|
| 14 | 구인배수 지도 — 타일 카토그램 70칸 + 선택 패널 |
| 15 | 센터별 구인 · 구직 — 좌우 대칭 막대, 같은 눈금 |
| 16 | 〈선택센터〉 상위 산업 · 직종 (접힘, 스위처 필터 미적용) |

**지도는 타일 카토그램**이다. 실제 경계로 그리면 중구·종로가 휴대폰에서 안 눌리고 넓은
군이 값을 크게 보이게 한다. 한 칸 = 한 시군구라 면적이 숫자를 왜곡하지 않는다.
색조가 시도(서울 초록 `#1baf7a` / 경기 파랑 `#2a78d6` / 인천 자주 `#b5478f`), 진하기가
구인배수다. 세 색조는 색각이상 분리도 검사를 통과했다(파랑↔자주 ΔE 12.2, 정상시각 22.7).

연동은 두 층이다.

- **상단 스위처**(직종/산업 + 대상) → 지도 색, 15번 막대 값
- **지도 칩**(수도권/서울/경기/인천) → 지도 범위, **15번 막대의 센터 목록**
- **타일 클릭** → 선택 패널(구 → 센터 + 대표 통계), 15번에서 그 센터 강조, 16번 카드
- 16번만 스위처를 따르지 않고 센터 전체를 본다

### 4.5 화면 규칙

1. **제공되지 않는 값은 카드째 감춘다.** 전국 값으로 대신 채우지도, 빈칸으로 두지도 않는다.
   (직종 소분류 선택 시 채용계획인원 카드, 산업별 탭의 구직 관련 전부)
2. **제목은 선택 대상 이름으로 시작한다.** 12자를 넘으면 줄인다. 랭킹·비교·지도처럼
   대상이 없는 카드는 축 이름으로 시작한다.
3. **시점 배지 색이 곧 출처다.** 초록 = 고용행정통계(월), 주황 = 직종별사업체노동력조사(반기).
4. **각주는 최소로.** 화면을 보면 아는 것은 적지 않는다. 남기는 것은 값을 잘못 읽게 만드는
   것뿐이다 — 구인배수 해석, 단위, 기준 시점.
5. **막대에 값을 직접 단다.** 초록(`#1baf7a`)이 배경 대비 2.74:1로 3:1 미만이라
   색만으로는 못 읽는다.

## 5. 수집

### 5.1 reportId를 하드코딩하지 않는다

`reptDtl.do?menuId=…` 페이지가 `reptIdUrl` 입력값에 현재 reportId를 들고 있다. 수집기는
menuId만 알고 매번 그 페이지에서 읽는다. EIS가 리포트를 재발급해도 깨지지 않는다.

| 자료 | menuId |
|---|---|
| 유효구인구직현황(전체) | `020010020` |
| 직종별 유효구인구직현황 | `050010060` |
| 산업/규모별 유효구인구직현황 | `050010080` |
| 구인구직취업현황(월) | `020010010` |

OLAP 데이터는 `POST /olap/report/cube/queries.do`로 오고, 그 앞에 `getSecretKey.do`로
세션 AES 키를 교환한다(`WISE.Util.SecureAjax.js`). 공식 오픈API가 아니라 BI 클라이언트의
내부 통신이므로 **헤드리스 브라우저(Playwright)로 화면을 열어 받는다.**

한 쿼리가 최대 5,000행, 엑셀 다운로드는 사실상 무제한이다. 수도권 70개 시군구 × 직종
중분류(약 35개) = 월 2,450행이 쿼리 한 번에 들어온다. **월 1회, 요청 몇 건**이면 끝난다.
이용지침이 금지하는 "과도한 트래픽"과는 거리가 멀다.

### 5.2 검사를 통과해야 커밋한다

조용히 틀린 값이 배포되는 것을 막는 것이 이 파이프라인의 첫째 목적이다.

- 시군구 70개가 다 왔는가 · 직종/산업 코드 집합이 지난달과 같은가 · 컬럼명이 그대로인가
- 총계 행과 분해값 합의 관계가 예상 범위인가
- 전부 0이거나 전월과 완전히 동일하지 않은가
- KOSIS는 표 이어붙인 경계에서 값이 튀지 않는가

**하나라도 어긋나면 커밋하지 않고 실패한다.** 기존 데이터는 그대로 두고, 화면 상단에
마지막 성공 시점을 띄운다. 센터가 오래된 값을 최신인 줄 알고 인용하는 일이 없어야 한다.

### 5.3 데이터 계약 규칙

테스트가 지킨다.

1. **유효구직건수의 분해값을 더해 총계로 쓰지 않는다.** 1인 다건이라 부풀려진다.
   총계가 필요하면 총계 행을 따로 받는다.
2. **유효는 월별 합산 금지.** 월말 재고라 합치면 크게 증가한다(EIS 주의사항).
3. **경기 일반구 코드 사용 금지.**
4. **인천 개편 전후 코드가 같은 달에 함께 값을 가지면 실패.**
5. **센터 매핑은 시군구 1:1**, 이중배정 0.

### 5.4 산출물

```
data/
  vacancy/summary.json      월 × 센터 × 직종 × 산업대분류 — 유효구인·유효구직
  vacancy/district/<코드>.json
  placement.json            취업건수
  insured.json              피보험자·취득·상실
  mobility.json             경력직 이동 (시도 × 산업대분류 × 이전 산업)
  est.json                  직종별사업체노동력조사 (반기)
  center_map.json           시군구 → 센터
  raw/<yyyymm>.csv.gz       OLAP 원자료 (재현용)
config/olap.json            menuId·레이아웃 정의
```

원자료를 gzip으로 커밋한다. 월 2,450행이라 3년치가 1~2MB 남짓이고, 이게 있어야 화면
숫자를 나중에 되짚을 수 있다.

## 9. 하지 않기로 한 것

- **신규구인·신규구직 노출** — 현장에서 쓰지 않는다. 취업건수만 그 리포트에서 가져온다.
- **오픈API 수집** — 구인이 구조적으로 0이고 IP 한도가 있다.
- **GitHub Actions 러너 IP로 한도 우회** — 이용지침 위반이고, 센터에 넘길 산출물이 그런
  토대 위에 서면 안 된다.
- **합성 지표** — 두 자료를 가중합한 지수는 가중치 근거를 댈 수 없고 센터가 인용했을 때
  방어가 안 된다.
- **실제 경계 지도** — 작은 자치구가 휴대폰에서 눌리지 않고 면적이 값을 왜곡한다.
- **총괄 연령 스위처** — 구인배수의 기준이 어긋난다.
- **고용형태 토글** — 전국 유효구인의 60%가 기간의 정함 없는 근로계약, 유효구직의 40%가
  '관계없음'이라 나눠도 쏠린다.
